# 岩迹数据模型（schemaVersion 1）

JSON 根对象包含 `schemaVersion: 1` 与 `sessions`、`climbs`、`training` 三个数组。导出还附带 `exportedAt` 和应用名称；导入只取白名单字段，不执行任何文件内容。

## sessions：一次训练

| 字段                  | 类型   | 含义 / 约束                                                                         |
| --------------------- | ------ | ----------------------------------------------------------------------------------- |
| id                    | string | 非空唯一 ID，最长 120 字符                                                          |
| date                  | string | 本地日历 YYYY-MM-DD，必须是真实日期，1900–2199 年                                   |
| venue                 | string | 场馆或地点，可空，最长 100 字                                                       |
| type                  | enum   | boulder 抱石、lead 先锋、toprope 顶绳、hangboard 指力板、strength 力量、cardio 有氧 |
| rpe                   | number | 整次训练的主观强度，1–10 整数                                                       |
| notes                 | string | 训练备注，最长 4,000 字                                                             |
| durationMinutes       | number | 整次训练分钟数，0–1,440 整数；非攀岩须大于 0                                        |
| source                | enum   | personal 个人 / example 示例                                                        |
| createdAt / updatedAt | string | 可解析的 ISO 日期时间                                                               |

## climbs：一次训练中的一条线路

| 字段      | 类型   | 含义 / 约束                                                               |
| --------- | ------ | ------------------------------------------------------------------------- |
| id        | string | 线路表内唯一 ID                                                           |
| sessionId | string | 必须指向存在的攀岩训练                                                    |
| grade     | object | `{ system: 'v' \| 'yds' \| 'french', value: string }`；取值必须在难度表内 |
| attempts  | number | 1–999 整数，Flash 须为 1                                                  |
| result    | enum   | flash / send / attempt / project                                          |
| notes     | string | 线路备注，最长 4,000 字                                                   |

抱石只接受 V 级，先锋和顶绳接受 YDS / 法式。攀岩训练至少包含一条线路。

Flash / Send 是已完成线路；Attempt 是一次训练中尝试过但未完成；Project 表示仍在持续攻线。后两者不计完攀。每个线路行只贡献一次结果，尝试次数单独记录。

## training：可选辅助训练动作

| 字段            | 类型   | 含义 / 约束                                 |
| --------------- | ------ | ------------------------------------------- |
| id / sessionId  | string | 动作唯一 ID / 存在的训练 ID                 |
| exercise        | string | 非空动作名称，最长 100 字                   |
| sets            | number | 1–999 组                                    |
| reps            | number | 每组次数，0–9,999；不适用时填 0             |
| weightKg        | number | 负重千克数，0–1,000，可小数；不表示辅助减重 |
| durationSeconds | number | 每组时长（秒），0–86,400；不适用时填 0      |

可以没有动作，只保存整次训练的时长和备注。动作时长不再加入整次训练总时长，避免重复统计。

## 写入、删除与合并

1. 仓库读取完整数据并校验；所有修改通过队列顺序执行。
2. 修改后的完整三表先通过校验，再以单次存储写入保存。校验失败或适配器报错时不更新 UI 成功状态。
3. 删除训练同步删除其线路和动作；清除示例仅匹配 `source: 'example'`。
4. 合并时以导入训练 ID 为集合，整体替换这些训练及其子行，其余记录保留。跨训练子行 ID 冲突整体拒绝。
5. 覆盖时使用导入的完整三表。UI 有独立确认勾选；损坏的现有数据库不会被仓库默默覆盖。

`StorageAdapter` 使用异步接口，方便替换为小程序或云端存储。但当前仓库的队列只保证**同一实例**内的顺序，不等于跨标签页或云端的事务。

## 日期与难度

统计周界从本地周一 00:00 到下周一 00:00。日期只用 YYYY-MM-DD 做区间比较；日期工具以本地年月日构造，避免 `toISOString().slice(0, 10)` 引起时区偏移。

难度用明确的顺序数组排序，不能直接按字符串排序（例如 V10 / V9、5.10a / 5.9）。抱石和绳索拒绝直接比较。法式近似映射用于绳索跨体系统计，原记录仍保留原始体系和难度。

示例 ID 由日期和训练类型构成，同一批示例重复载入可合并。示例根据打开当天生成最近 8 周，不创建未来训练；清除示例后可以重新体验。

用于手工导入检查的最小文件在 `tests/fixtures/import-valid.json`；它属于验证数据，不是训练建议。
